Data Wrangling with dplyr

Instructor-led tutorial using palmerpenguins

Author

Dr. Bigman (with help from Allison Horst)

Overview

In this tutorial, we will use dplyr to practice common data-wrangling tasks in R. We will work with the penguins data from the palmerpenguins package.

By the end of the tutorial, you should be able to:

  • use filter() to keep observations that meet specified conditions;
  • use select() to keep, remove, or reorder variables;
  • use relocate() to move variables without dropping any columns;
  • use rename() and rename_with() to change variable names;
  • use mutate() to create or modify variables;
  • combine group_by() with summarise() to calculate grouped summaries;
  • use across() to apply the same operation to multiple variables;
  • use count() to quickly count observations by groups; and
  • use case_when() to create variables from multiple logical conditions.
  • understand the basics of joins (e.g., left_join), strings, working with dates and times, rounding, logarithms, regular expressions, and factors
Note

This lesson is an instructor-led adaptation inspired by Allison Horst’s Wrangling penguins: some basic data wrangling in R with dplyr LearnR tutorial. The structure and explanations here have been rewritten for a classroom Quarto workflow, and current dplyr syntax is used where the package has changed.

Source: https://allisonhorst.shinyapps.io/dplyr-learnr/

filter(): keep rows

Use filter() when you want to keep observations that satisfy one or more conditions.

The general structure is:

data |>
  filter(condition)

The pipe operator

The native R pipe, |>, can be read as “and then.” We call this the native version because R did not used to have a native version and just had a dplyr version, %>%. If you ever see %>%, it is the same thing.

penguins |>
  filter(species == "Chinstrap")

This means: start with penguins, and then filter the rows of observations with Chinstrap penguins.

group_by() + summarise(): summaries by group

Often, you will want to summarize data so to find out certain things about your data. For the penguins example, we may want to know:

What is the mean body mass for each species? How many penguins were observed on each island? What is the mean flipper length for males and females within each species?

group_by() tells dplyr which groups should be treated separately. summarise() then calculates one or more summary statistics for each group.

Without grouping, summarise() returns an overall summary. If we run the code below, we get a mean mass for all penguins. But that is not very useful.

penguins |>
  summarise(
    mass_mean = mean(body_mass_g, na.rm = TRUE)
  )
# A tibble: 1 × 1
  mass_mean
      <dbl>
1     4202.

With grouping, the same calculation is performed separately for each group.

One summary by one group

Calculate mean body mass by species.

penguins |>
  group_by(species) |>
  summarise(
    mass_mean = mean(body_mass_g, na.rm = TRUE)
  )
# A tibble: 3 × 2
  species   mass_mean
  <fct>         <dbl>
1 Adelie        3701.
2 Chinstrap     3733.
3 Gentoo        5076.

across(): apply a function across columns

across() is useful when you want to apply the same function to several variables. It is commonly used inside summarise() or mutate().

Suppose we want the mean of every measurement variable ending in mm, separately by species.

We could write each calculation individually:

penguins |>
  group_by(species) |>
  summarise(
    bill_length_mean = mean(bill_length_mm, na.rm = TRUE),
    bill_depth_mean = mean(bill_depth_mm, na.rm = TRUE),
    flipper_length_mean = mean(flipper_length_mm, na.rm = TRUE)
  )
# A tibble: 3 × 4
  species   bill_length_mean bill_depth_mean flipper_length_mean
  <fct>                <dbl>           <dbl>               <dbl>
1 Adelie                38.8            18.3                190.
2 Chinstrap             48.8            18.4                196.
3 Gentoo                47.5            15.0                217.

Or we can use across():

penguins |>
  group_by(species) |>
  summarise(
    across(
      ends_with("mm"),
      ~ mean(.x, na.rm = TRUE)
    )
  )
# A tibble: 3 × 4
  species   bill_length_mm bill_depth_mm flipper_length_mm
  <fct>              <dbl>         <dbl>             <dbl>
1 Adelie              38.8          18.3              190.
2 Chinstrap           48.8          18.4              196.
3 Gentoo              47.5          15.0              217.

We first group_by species and then take the mean across all columns that end in mm. To do so, we put the across and mean functions inside summarise.

The selection rules inside across() use the same “tidyselect” helpers that work in select().

Note

Current dplyr syntax places extra function arguments such as na.rm = TRUE inside an anonymous function: ~ mean(.x, na.rm = TRUE). Older examples may show across(..., mean, na.rm = TRUE).

The above code renames the summarized (new) columns with a pattern - max_ + the column name.

Applying multiple functions

You can also apply multiple functions at once. Say you wanted to calculate the mean and standard deviation for variables containing length and give the resulting columns new names.

Use list() to provide multiple functions to across(). Here, we name the functions avg and stdev.

The .names argument controls how the new columns are named. Within .names, {.fn} is a placeholder for the function name (avg or stdev) and {.col} is a placeholder for the original column name.

Because we specify: .names = "{.fn}_{.col}", {dplyr} combines the function name and column name. For example, the mean of bill_length_mm will be named avg_bill_length_mm, and its standard deviation will be named stdev_bill_length_mm.

penguins |>
  group_by(species) |>
  summarise(
    across(
      contains("length"),
      list(
        avg = ~ mean(.x, na.rm = TRUE),
        stdev = ~ sd(.x, na.rm = TRUE)
      ),
      .names = "{.fn}_{.col}"
    )
  )
# A tibble: 3 × 5
  species   avg_bill_length_mm stdev_bill_length_mm avg_flipper_length_mm
  <fct>                  <dbl>                <dbl>                 <dbl>
1 Adelie                  38.8                 2.66                  190.
2 Chinstrap               48.8                 3.34                  196.
3 Gentoo                  47.5                 3.08                  217.
# ℹ 1 more variable: stdev_flipper_length_mm <dbl>

  • {.col} means the original variable name.
  • {.fn} means the name assigned to the function in the function list.

case_when(): create values from conditions

case_when() is useful when a new variable depends on several possible conditions. It is commonly used inside mutate().

The basic pattern is:

data |>
  mutate(
    new_variable = case_when(
      condition_1 ~ value_1,
      condition_2 ~ value_2,
      .default = default_value
    )
  )

Conditions are evaluated from top to bottom, so their order can matter.

Create a new variable called size_bin that categorized body mass into distinct bins. penguins |>

Introduction to advanced wrangling

joins

There are two main types of joins: mutation joins and filtering joins.

Mutating joins add new variables to one data frame from matching observations in another.

Filtering joins filter observations from one data frame based on whether or not they match an observation in another.

For this section, we will be working with nycflights13 a compilation of datasets that contains information about all flights that departed from NYC (e.g. EWR, JFK and LGA) to destinations in the United States, Puerto Rico, and the American Virgin Islands) in 2013. The explanations and code used here are modified from Chapter 19 of Hadley Wickham’s R for Data Science.

library(nycflights13)

To understand joins, you need to first understand how two tables can be connected through a pair of keys, within each table. In this section, you’ll learn about the two types of key and see examples of both in the datasets of the nycflights13 package. You’ll also learn how to check that your keys are valid, and what to do if your table lacks a key.

Now we can use foreign keys to match information from these other data frames to flights so we can learn more about each flight. A foreign key is a variable (or set of variables) that corresponds to a primary key in another table. For example:

flights$tailnum is a foreign key that corresponds to the primary key planes$tailnum. flights$carrier is a foreign key that corresponds to the primary key airlines$carrier. flights$origin is a foreign key that corresponds to the primary key airports$faa. flights$dest is a foreign key that corresponds to the primary key airports$faa. (flights$origin, flights$time_hour) is a compound foreign key that corresponds to the compound primary key (weather$origin, weather$time_hour).

A mutating join allows you to combine variables from two data frames: it first matches observations by their keys, then copies across variables from one data frame to the other. Like mutate(), the join functions add variables to the right, so if your dataset has many variables, you won’t see the new ones. Strings

In R, a string is text. Strings are stored as character values and are usually written inside quotation marks. The {tidyverse} has a package called {stringr} that makes working with strings easier and more consistent. There is a lot to learn here and we will just touch on the basics. For more information, check out the package documentation.

There are four main families of functions in {stringr}:

  1. Character manipulation: these functions allow you to manipulate individual characters within the strings in character vectors.
  2. Whitespace tools to add, remove, and manipulate whitespace.
  3. Locale sensitive operations whose operations will vary from locale to locale.
  4. Pattern matching functions. These recognise four engines of pattern description. The most common is regular expressions, but there are three other tools.

Let’s go over the most common uses. For this, we will work with a vector of 3 strings:

species <- c(
  "  Sandbar Shark",
  "BLACKTIP SHARK  ",
  "Lemon Shark"
)

There is extra space around the first string so use str_trim to remove it:

species <- str_trim(species)

species
[1] "Sandbar Shark"  "BLACKTIP SHARK" "Lemon Shark"

The capitalization is a mess. Let’s fix it by making it all lowercase:

species <- str_to_lower(species)

species  
[1] "sandbar shark"  "blacktip shark" "lemon shark"

We can ask if the vector of strings contains a specific string, “Shark”:

str_detect(species, "Shark")
[1] FALSE FALSE FALSE

Remember, R is case sensitive.

str_detect(species, "shark")
[1] TRUE TRUE TRUE

We can replace a string or part of a string:

# Replace text
str_replace(species, "lemon", "yellow")
[1] "sandbar shark"  "blacktip shark" "yellow shark"

Let’s look a more realistic data wrangling example. We first create a small tibble called fish with two columns: sample_id (an ID that contains both the state abbreviation and a sample number) and species (species names that are inconsistently formatted). Then we use mutate() to clean and create variables:

str_trim(species) removes extra spaces from the beginning and end of the species names. Here, " sandbar shark " becomes "sandbar shark".

str_to_title(species) standardizes capitalization so each word begins with a capital letter. "sandbar shark" becomes "Sandbar Shark" and "BLACKTIP SHARK" becomes "Blacktip Shark".

str_sub(sample_id, 1, 2) takes the first two characters from each sample_id and stores them in a new column called state. "DE-001" becomes "DE" and "NJ-003" becomes "NJ".

fish <- tibble(
  sample_id = c("DE-001", "DE-002", "NJ-003"),
  species = c(" sandbar shark ", "BLACKTIP SHARK", "Lemon Shark")
)

fish |>
  mutate(
    species = str_trim(species),
    species = str_to_title(species),
    state = str_sub(sample_id, 1, 2)
  )

Dates and Times

Dates and times are hard because they have to reconcile two physical phenomena (the rotation of the Earth and its orbit around the sun) with a whole raft of geopolitical phenomena including months, time zones, and DST. This tutorial won’t teach you every last detail about dates and times, but it will give you a solid grounding of practical skills that will help you with common data analysis challenges.

For more information, consult Chapter 17 of R for Data Science and the lubridate package.

Dates and times are common in real datasets, but R needs to know that a variable represents a date or date-time before we can easily work with it. The {lubridate} package, which is part of the {tidyverse}, provides functions that make working with dates and times easier.

Dates versus date-times

R distinguishes between a date, which contains a year, month, and day, and a date-time, which also contains a time of day.

We can get today’s date with today() and the current date and time with now():

today() # date
[1] "2026-08-10"
now() # date-time
[1] "2026-08-10 10:41:30 EDT"

We can check how R stores these objects using class():

class(today())
[1] "Date"
class(now())
[1] "POSIXct" "POSIXt"

Dates are generally displayed using the format YYYY-MM-DD; For example 2026-08-10 means August 10, 2026.

Converting Character Strings to Dates

Dates are often imported into R as character strings rather than as actual dates.

For example:

date <- "2026-08-10"

date
[1] "2026-08-10"
class(date)
[1] "character"

Although this looks like a date to us, R currently sees it as text.

We can use functions from lubridate to convert character strings into dates.

The name of the function tells R the order in which the components of the date appear:

ymd() = year, month, day mdy() = month, day, year dmy() = day, month, year ymd(“2026-08-10”)

mdy(“August 10, 2026”)

dmy(“10-Aug-2026”)

A useful rule is:

Look at the order of the year, month, and day in your data and choose the corresponding lubridate function.

For example:

date <- ymd(“2026-08-10”)

class(date)

R now recognizes this variable as a date rather than as character text.

Putting it all together

A typical dplyr workflow combines several verbs rather than using one function in isolation.

For example, suppose we want to compare average body size among female penguins by species and island.

penguins |>
  filter(sex == "female") |>
  mutate(body_mass_kg = body_mass_g / 1000) |>
  group_by(species, island) |>
  summarise(
    n = n(),
    mean_body_mass_kg = mean(body_mass_kg, na.rm = TRUE),
    sd_body_mass_kg = sd(body_mass_kg, na.rm = TRUE),
    .groups = "drop"
  ) |>
  relocate(n, .after = island)
# A tibble: 5 × 5
  species   island        n mean_body_mass_kg sd_body_mass_kg
  <fct>     <fct>     <int>             <dbl>           <dbl>
1 Adelie    Biscoe       22              3.37           0.343
2 Adelie    Dream        27              3.34           0.212
3 Adelie    Torgersen    24              3.40           0.259
4 Chinstrap Dream        34              3.53           0.285
5 Gentoo    Biscoe       58              4.68           0.282

When reading a pipeline, read from top to bottom:

  1. start with the data;
  2. keep the observations you need;
  3. create or modify variables;
  4. define groups;
  5. calculate summaries; and
  6. arrange the output variables for readability.

Final practice

How would you wrangle the data to determine, among penguins observed in 2008 and 2009 with known sex, how many males and females of each species fall into small (< 4.5 kg) versus large (≥ 4.5 kg) body-mass categories?

Hint:

  1. Keep observations from 2008 and 2009.
  2. Exclude observations with missing sex.
  3. Create body mass in kilograms.
  4. Create a body-mass category:
    • "large" for body mass at least 4.5 kg
    • "small" otherwise
  5. Count penguins by species, sex, and body-mass category.
# Write your code here
TipSolution 
penguins |>
  filter(year %in% c(2008, 2009), !is.na(sex)) |>
  mutate(
    body_mass_kg = body_mass_g / 1000,
    mass_category = case_when(
      body_mass_kg >= 4.5 ~ "large",
      body_mass_kg < 4.5 ~ "small",
      .default = NA_character_
    )
  ) |>
  count(species, sex, mass_category)

Summary

The dplyr functions covered in this tutorial answer different types of data-wrangling questions:

Question Function
Which observations do I want? filter()
Which variables do I want? select()
Where should variables appear? relocate()
What should variables be called? rename()
What new variables do I need? mutate()
What summaries do I need by group? group_by() + summarise()
Can I repeat the same operation across variables? across()
How many observations are in each group? count()
Can I assign values based on several conditions? case_when()

The main idea is that these verbs can be chained together with |> to build a readable sequence of data-wrangling steps.
